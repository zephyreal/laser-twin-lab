# 设备数字孪生后台

前端位于 `/twin/`，可独立托管于 GitHub Pages。

## 当前状态

- 学号登录、课程角色、学生账号创建、本人历史成绩、教师成绩导出已实现前后端代码。
- 配置项目 URL 与 publishable key 之前，页面只开放访客练习并明确标注，不接受正式登录。
- 不向公共仓库提交密码、service_role key 或访问令牌。

## 接入步骤

1. 在 Supabase 建立专用项目，确认费用和地域。
2. 将 `schema.sql` 通过已授权的数据库工具应用一次，启用的 RLS 只允许学生读取自己数据，禁止客户端直接写状态或分数。
3. 部署 `functions/twin-api/index.ts`，携带 `_shared/rules.mjs`。函数自行调用 Auth 服务验证用户令牌；任何业务操作都要求已建课程档案。使用默认服务端 `SUPABASE_URL` 和 `SUPABASE_SERVICE_ROLE_KEY`，不复制到前端。按项目 JWT 签名配置决定 gateway verify_jwt；若关闭网关校验，仍必须保留函数内 get-user 验证。
4. 使用 Auth 管理 API 或 Supabase 控制台创建第一个教师账号，账号邮箱别名为 `teacher@students.laser-twin.invalid`。此地址仅作身份映射，不收邮件，不发送邀请。由教师私下设置强密码。不要在 SQL 中存明文密码或直接修改 auth 内部表。
5. 将 Auth 返回 UUID 写入 `twin_profiles`，student_id 为 `teacher`，role 为 `teacher`。身份以该受保护的课程表为准，不能使用用户可修改的 metadata 授予角色。
6. 在 `twin/config.js` 写入项目 URL 和公开 publishable key。重新发布 GitHub Pages。
7. 教师登录「我的成绩 → 教师成绩后台」创建学生账号。学生首次登录后修改密码。当前为教师发放账号模式，无自助注册；无课程档案的 Auth 用户被 API 拒绝。
8. 运行账号隔离、非法状态/得分写入、重复提交、8 秒计时、教师权限和完整流程测试。运行数据库安全检查。未通过测试不得将后台标记为完成。

## 评分和记录

- 正式操作通过 Edge Function 服务端状态机更新；忽略客户端成绩、时间、用户 ID 与状态。
- 每次写入对版本号做条件更新，防止并发覆盖。提交不可逆改分，重复提交返回原成绩。
- 设备准备 30、参数 20、焊接 20、规范停机 20、联锁操作 10。
- 工艺窗口仅作教学设定。访客反馈与正式成绩分开，访客成绩不会上传。
- 教师只能查看本项目课程；后续多教师多课程需增加课程成员授权，不能直接复用全局教师角色。
- 每名学生每分钟最多开始 5 次，一次最多 240 个事件；教师列表最多 1000 条，应在扩展班级规模时增加分页。
- 可验证请求顺序和服务器计时，不能证明实际由学生本人点击，不能将其作为防作弊考试平台。
